zest

A staging tool for Zig executables. Point it at any git repo, a host shorthand, or a Zigistry name. It clones, builds in ReleaseSafe on your machine, and links the binary — no prebuilt artifacts to trust.

Zig 0.16 MIT Linux · macOS · Windows
01Install

One command, no root required

Linux & macOS
curl -fsSL https://justinwoodring.github.io/zest/install.sh | sh
Bootstraps a checksum-verified private Zig toolchain if you don't have one.
Windows
irm https://justinwoodring.github.io/zest/install.ps1 | iex
PowerShell 5.1+. Same protection and upgrade model.

Already installed? The script hands over to zest self-update. The bin directory holds zest and every tool it installs, so the installer offers to add it to your PATH and your tools run by bare name. For automation: sh -s -- --yes / --no (PowerShell: -Yes / -NoPath). Pre-built binaries live in Releases.

02Use

Install, run, upgrade

A git URL, a host shorthand, or a short name from the Zigistry registry. Tags, branches, and commit hashes all work.

$ zest install github.com/user/my-cli-tool
$ zest run my-cli-tool --help
$ zest update my-cli-tool
# or try anything without installing it first:
$ zest run github.com/user/my-cli-tool --version

04Inspect

Know before you install

zest inspect reads a project and reports whether zest can install it, whether the declared version trails the latest upstream tag, and how the package appears in the registry. It never builds and never writes state.

$ zest inspect .
zest inspect  my-cli-tool
location      .
version       1.4.2   (upstream v1.5.0, OUT OF DATE: `zest update my-cli-tool`)
minimum zig   0.16.0
description   A command-line tool for doing things.
license       MIT
author        Ada Lovelace <ada@example.com>
remote        https://github.com/user/my-cli-tool
zigistry      indexed  https://github.com/user/my-cli-tool  (43 stars)  (same repo as remote)
programs      my-cli-tool
verdict       installable  (zest installs "my-cli-tool")

What it reads

SourceWhat zest inspects
build.zigEvery addExecutable target and its .name (computed names are marked dynamic).
build.zig.zonDeclared name, version, and minimum zig version.
README.mdFirst prose paragraph, as the description.
LICENSESniffed for MIT, Apache-2.0, GPL, BSD, ISC, MPL, or Unlicense.
gitLast commit author and the origin remote.
upstreamLatest tag via git ls-remote --tags, compared to the declared version.
ZigistryRegistry visibility, matching repo, stars, and collision candidates.

Verdicts

The verdict mirrors what zest install will do: installable (one program, or one named after the tool), ambiguous (several programs, none matching, so zest refuses to guess), no_binaries, or not_zest_project. The exit code is 0 only for installable.

05Why

Built like a release engineer would want it

Tagged first
zest tracks the latest semantic-version tag, never master, and only falls back to the default branch when a repo has no tags.
Any source
Git URLs, host shorthand, or short names resolved through Zigistry. Tags, branches, or commit hashes.
Self-protecting
The name zest is reserved. No package can overwrite, shadow, or remove the zest binary; only zest self-update can.
No TOFU
No trust-on-first-use binaries. Everything compiles locally with the real Zig build pipeline in ReleaseSafe.
Cross-platform
Linux (x86_64, arm64), macOS (arm64), and Windows (x86_64, arm64). Every tag ships binaries for all five.
Atomic
Manifest writes, installs, and self-upgrades are atomic, so a failed build never damages an existing install.
06Upgrade

Everything, including zest

Every tool updates with one command, and zest upgrades itself the same way, from tagged releases, without letting another package touch it.

$ zest update my-cli-tool
$ zest self-update
$ zest list
# NAME          VERSION  SOURCE
# my-cli-tool    v1.4.2   https://github.com/user/my-cli-tool
